CARTESIAN FORM OF RADAR IMAGES:


	You need the following files: 
					radar_scans.txt
					*_catesian_grid_output_*.txt 
						m_ , h_ , or a_ as possible prefixes
						_(number) for the scan number/id.
						for each scan number you will need all three forms (m, h and a).

	you need to edit and run the following test files in the tests/ folder:

				test_radar.c
				test_processing.c



	instructions for:

					radar_scans.txt

						IN test_radar.c						

						set the radar parameters to your likining:
							scanning type, location and height in reference plane, max resolution and rnage resolution. and angular resolution.
						
						set your raincell parameters (these still will change) in create_raincell() function. 

						define the radar motion in create_spatial_raincell() function. 
	
						Determine the sampling times for the radar  by changing the time parameter in teh first for loop. 

						run the test file test_radar.c


					*_cartesian_grid_output_*.txt

						IN test_processing.c

						set the target_radar_id to the right id... otherwise there will be no output. 

						set the cartesian grid resolution as you like. 

						fun the test file test_processing.c

	Getting to the graphs:

		The graphs are either the attenuation ("amount" of attenuation), the height of the radar beam, or which part of the raincell the radar sampled from. 
	
			For the graph in polar coordinates (based on the radar_scans.txt): 

				run $ python visualisations/plotpolarpointdata.py 
						THEN select the radar_scans.txt file with the number. 

			For the attenuation, height and sampling plots in cartesian coordinates
				run $ python visualisations/plot_cartesian_grid2.py

		The plots can be found in the plots folder in the repository. 				




GRAPHS FOR TRUE VS MEASURED COMPARISON (folders F),

	you need files in the :
				stats.txt,
				radar_scan_0000.txt, (with other numbers...)
				disp_g_0000.txt, (with other numbers.... 0000 up to and including 0053 in my case.)
				true_g_0000.txt, (with other numbers.... 0000 up to and including 0053 in my case.)
	

	you need to edit and run the following test files in the tests/ folder:

				test_command_centre.c
				test_volume_scan.c



	instructions for:

					radar_scan_0000.txt (and others like it)

						IN test_command_centre.c						

						set the start and end time of each command (the volume scan):
							the volume scan is defined as a fixed 16 PPI scans every 5 minutes.
							The radar id scanned with is set in the command_centre.c file. should still be changed. 
	
						set your raincell parameters (these still will change) in create_raincell() function. 

						define the radar motion in create_spatial_raincell() function. 	

						set your VPR parameters (in the fill_VPR_params() function).

						define the radar types. 

						run the test file test_command_centre.c


					disp_g_*.txt
					true_g_*.txt
					stats.txt

						IN test_eval_scans.c

						set the NUM_SCANS to the right amount in the definition at the top. 

						ensure that the VPR, the radars, the raincells are all the same.	

						set the cartesian grid resolution as you like. 

						run the test file test_eval_scans.c

	Getting to the graphs:

		The graphs are a graph of the statistics over the simulation time, or an animation of the measured vs true raincell to help understand the graph. 
	
			For the graph of stats (based on the stats.txt): 

				run $ python visualisations/extra_scan_stats.py 

			For the animation
				run $ python visualisations/animate_full_time.py

		The plots can be found in the plots folder in the repository.

RUNNING TESTS:
			
	Ensure you are in the base folder (Repo).

	run $ make test
	
		THEN the available tests will be listed, pick one using the number pad. 





To run a single process with a single set of parameters with all the data produced, change the data in the relevant .c files. Then run 'make test' and then select test_chain_1.c. Afterwards then run 'python3 visualisations/testB.py' with 'conda activate cDev' ensure that the outputs/ folder has no .txt files.... 


To generate a list of parameters you want to test, run './generate_parameters.sh' then once you have that, then run 'make parallel-batch-test TEST=test_pcl PARAM_FILE=params.txt CORES=8' and then you get some results in a batch folder. 

THEN: to generate the emd (distance metric) file run './compute_emd batch_test_20260507_135918' in the right batch_test folder.
./compute_mse_exec batch_test_20260518_153537 for the MSE
./compute_mse_exec batch_test_20260518_153537 for the Bias
Then to generate the statistical analysis run 'python3 results_analysis/complete_analysis.py batch_test_20260507_135918/emd_results.txt '
change the text file name to change the analysis being done for either emd, mse or bias. 

You can also add flags, for doing the analysis within a certain range of one of the parameters... 

AND BOOOM!!! 



To run a combined processing, have a params.txt file in the home directory in the form of -r 1000 -m 170 -c 500 -k .2000000000 -y 15000.0000000000 -a 8.7500000000
 (It should be one line). 

Then you run make test test_multi_radar_pcl.c

And you should be good. Here the noise in the true attenuation per km, the noise in the radar, and the attenuation sensitivities parameters (climatorlogyically determined) have an effect on the result. The stdev should never be more than 5dB in the vertical profile. Otherwise the results are garbage.
