THIS IS TO GUIDE YOU TO GETTING AND REPRODUCING YOUR RESULTS: 

		instruction manual to getting to figures in the worked example. 

		To run this programme, download the codebase onto your computer.
		Ensure you have a C compiler (gcc or otherwise) and python with numpy and matplotlib installed.
		This programme was developed and tested using vim and bash scripts and runs easily on the command line.
		The instructions given assume use on the command line.
		For use in other integrated development environments, please translate the instructions accordingly.




NOTES:

	NOTE: you need to add the following directories within your local repository:  "archive/", "build/", "inputs/", "outputs/",  "logs/".   

	NOTE: you need some form of a C compiler. gcc for instance.

	NOTE: you need python and some basic packages (numpy, matplotlib) installed for the data-visualisation steps.



STEPS

	STEP 1:	DEFINE RADAR AND RAINCELL PARAMETERS
		in src/analysis.c in the function intial_test_environment():
		setup the correct radars (position, resolutions, frequencies, etc.) using the create_radar() function
			add each radar to the radar list.
		setup the correction rain evolution parameters when the function fill_VPR_params() is called
		setup the material and spatial descriptions of the rain in create_raincell() and create_spatial_raincell()
			add each raincell to the raincell list.


	STEP 2: DEFINE RADAR SCANNING PATTERN.
		in src/command_centre.c create a generate_commands_file_*() function which suits your needs.
		for each radar defined previously, define a scanning pattern done in the 5 minute interval.
		The existing generate_commands_file*() functions can be used as guidance.
		Do not forget to also define the new function prototype in the include/control_centre.h file. (the "function_type function(arguments);" not anything within the curly brackets in the .c file.)

	STEP 3: DEFINE THE SUBSEQUENT PROCESSING CHAIN(S) USING THE PRODUCED RADAR DATA
		in src/processing.c create a compute_display_grid_*() function which suits your needs.
		the processing takes interpolated radar scans, and populates a Vol_scan structure with height, reflectivity, true and estimated attenuation, and rain-type.
		the Vol_scan structure is then used as an arguement in the compute_display_grid*() function. 
		follow the KNMI example as inspiration. 
		if necessary, implement helper functions.
		Do not forget to also define any new function prototypes in the include/processing.h file as above.
		
	
	STEP 4: RUN THE SIMULATION TO GENERATE RADAR DATA AND THE PRODUCT DATA
		run the following code to make an executable bash script: 
			chmod +x combi_test.sh
		then run the script using 
			./combi_text.sh

		In the outputs/ folder:
			- the simulated measurements of the RHI's are stored (cg_att_corr_measurements*.txt)
			- the true measurements of the RHI's are stored (cg_true_reflect*.txt)
			- the simulated ground-reflectivity values based on the C-band radar data are stored (disp_C_g*.txt)
			- the simulated ground-reflectivity values based on the X-band radar data are stored (disp_X_g*.txt)
			- the true ground-reflectivity values are stored (true_g*.txt)
			- the raw radar reflectivity retrievals are stored (radar_0[0,1,2]_scan*.txt)
			- the statistics on the predicted rainfall rates are stored (stats_[C,X].txt)
			- the parametrisations of the VPR's (both stratiform and convective) are stored (VPR_conv*.txt, VPR_strat*.txt)
			- the empirically determined binned VPR's are stored (vpr_emp_[conv,strat]_[C,X,rhi].txt)
			- the true binned VPR's are stored (vor_true_[conv,strat].txt)



	STEP 5: RUN THE DATA VISUALISATION CODE. 
		run the following code to generate the ground-reflectivity comparison between the C-band and X-band radars and the true values as seen by the PPI-based volume scans:
			python data_vis/gridded_qpe_product.py
			
				the figures are stored in the repository folder (grid_comparison.[pdf/png])
		
		run the following code to generate the statistics on the 5-min interval rainfall depths:
			python data_vis/stats_plot.py
					
				the figure is stored in the repository folder (stats_comparison.[pdf,png])

		run the following code to generate the RHI reflectivity data: 
			python data_vis/rhi_visualisation.py

				the figure is stored in the repository folder (rhi_comparison.[pdf/png])

		run the following code to generate the vpr comparisons for the rhi data:
			python data_vis/vpr_at_peak.py

				the figure its stored in the repository folder (vpr_comparison.[pdf/png])

		OR: run the following bash script:

			for f in data_vis/*.py; do ["$f"="stylesheet.py"] && continue; python "$f"; done



COMPUTATIONAL STUDY: 

		In order to test the interaction between different components, some programming is needed. 
		I will explain how I changed the programme for a specific experiment.
		Please adapt the explanation to your situation.

	STEP 1: DETERMINING THE VARIABLES YOU WANT TO VARY, AND AT WHICH LEVELS.
		This step does not require any coding, but just some thought.
		I want to change 7 variables at three different levels. 

	STEP 2: ADAPT CONFIGURATION FILES TO SUIT YOUR NEEDS
		- in the file src/analysis.c, 
			*for the function initialize_test_environment() I ensure I have six double's as input parameters (x1,...,x7)
			*for changes in vertical structure or core development rates, incorporate your variable correctly into the fill_VPR_params() function.	
			*for changes in the raincell parameters, incorporate your variable correctly into the create_raincell() and create_spatial_raincell() functions. 
			*for changes in radar parameters, incorporate your variable correctly into the create_radar() functions.

		- in the file include/analysis.h,
			* ensure the function prototype matches, i.e. have the same input variables as the function defined in the analysis.c file. 
		- in the file tests/test_multi_radar_pcl.c
			* alter the CommandLineParams structure to include all your variables.
			* change the parse_command_line() function of the right default values for each variable in the definition of the CommandLineParams, and change the cases for the each parameter. Also change the help function print_usage().

	STEP 3: CHANGE THE BATCH GENERATION SCRIPT TO INCLUDE YOUR NEW VARIABLES.
		- alter the generate_params.sh script.


	STEP 4: CHANGING THE MAKEFILE TO TEST HIGHER RESOLUTION DATA:
		- you go to the definitions of batch-test, batch-test-parallel, and adaptive-batch-test-parallel,
		- For each parameter, you change the number of digits for the integer, and you add a multiplier to avoid decimals. you add a fractional number as a way to round. 

	STEP 5: GENERATE PARAMETERS:
		- compile the generate_params.sh script using chmod +x generate_params.sh
		- go through the programme to generate the parameters of your chosing.
		OR
		- use a params.txt file in a batch_test... folder, and move it to the base directory. then proceed to STEP 6.  
	
	STEP 6: RUN THE TEST USING THE COMMAND:
		- make adaptive-parallel-batch-test TEST=test_multi_radar_pcl PARAM_FILE=params.txt CORES=4 [or however many cores you have]
		- this generates a timestamped folder with statistics files for a lone C-band radar, a lone X-band radar, a combined C-X radar processing, and an adaptive C-X scanning strategy. 

	STEP 7: PROCESS THE STATS FILES INTO DISCREPANCY IN TOTAL RAINFALL DEPTH
		- chmod the files data_vis/compte_sums_for_x_and_c.c, /compute_ad_sums.c, /quatro_compute_sums.c
		- run them depending on what you want to see, for the behaviour of either individual radars do compute_sums_for_x_and_c.c, for adaptive compared to C-band you have to run the compute_ad_sums, for the full analysis as in the second-to-last section in the paper, do quatro_compute_sums.c. 

	STEP 8: RUN AN ANOVA
		- depending on whether you are doign the initial or a revised anova, run either "python data_vis/cs_anova_initial.py" or "python data_vis/cs_anova_quadratic_model.py"
		- the anova's are saved in the figures/ folder. 

	STEP 9: ONCE YOU HAVE DECIDED YOUR RESPONSE SURFACE TO TEST AND RUN
		- go do STEPs 5 and 6 and 7 again. 
		- then you run the python script "python data_vis/3D_responces_surface.py" for the 3D response surface for all four combinations
		- then you run quad_2d_discr_maps.py in the same directory for the 2D response surfaces for the products involving the C-band.
		- then you run the discrepancy_histogram_scatter.py in the same directory for the histogram of the discrepancies for products involvign the C-band
		- all figures are stored in the figure/ directory.
